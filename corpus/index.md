- [decisions](wiki/decisions.md) — The locked calls behind imbatranim-office: its own repo installed as one suite descriptor, TypeScript with editing in the browser, kit apps on the desktop's shared kit, the crafts as reference only, PDF Viewer and norPDF merged, and office-* app ids, with what each rejected and why. - [glossary](wiki/glossary.md) — The suite's vocabulary: suite, suite descriptor, kit app, shared kit, kit snapshot, built-in, parity, retire, craft, and the five app names (Docs, Sheets, Slides, PDF, CAD), with the synonyms each displaces.
- [open-questions](wiki/open-questions.md) — What is genuinely unresolved for imbatranim-office. One question as of 2026-10-28, from brief 14: keep the suite a service descriptor (DWG opens, but every Office window waits for the suite server's cold start and fails with it) or ship it static until the OS can lease a server per app. CAD's engine, Slides' save strategy and how LibreDWG runs are settled; see decisions.md.
- [overview](wiki/overview.md) — What imbatranim-office is: the office apps of imbatranimOS (Docs, Sheets, Slides, PDF, CAD) in their own repo, installed from the OS's Marketplace as one entry and rendered with the desktop's own React and kit, and where it came from.
- [pdf](wiki/pdf.md) — PDF (apps/pdf), the OS's PDF Viewer and norPDF merged into one app, and @pdfcore/engine (packages/pdfcore-engine), moved from imbatranimOS 56e23b7 — what each module owns, the fast first page (pdf.js alone, the engine and editing tools after it), the shared pdf.js worker file, the save→reload cache contract, what the write path is proven to preserve, the timing (standalone, and in the OS where the suite is 40 ms behind PDF Viewer), and what is deliberately not supported.
- [slides](wiki/slides.md) — How Slides (brief 04) is built — a .pptx opened as its OPC package with a lossless XML tree, edited in place and saved by copying every untouched part byte for byte — with the spike that proved it on three real decks, what a save keeps and changes, the renderer that both views and edits, undo, the file wiring, and the known gaps.
- [status](wiki/status.md) — Current snapshot (2026-10-28): all five apps built on main and walked in the OS; briefs 01–15 done (12 Docs caret lived with; 13 Sheets' formulas in a worker; 15 formulas past row 1000 compute, the big first calculation a todo; 14 CAD opens DWG through the suite's first server, LibreDWG as wasm in Node); the owner decides whether the suite stays a service descriptor (every Office window waits on the server); no brief left in todo; nothing pushed.
- [stylesheets](wiki/stylesheets.md) — How an app's CSS reaches the desktop: app.css as Tailwind utilities only against the kit snapshot's tokens (no preflight, no --color-* values), and vendor stylesheets declared in package.json (imbatranimOffice.vendorStyles), copied byte for byte after a check that refuses rules not tied to the library, html/body/:root rules beyond custom properties, the desktop's tokens, @import, @font-face and remote url(); ownAttributes, ownCustomProperties (Univer's --univer-) and dropRules (Univer's scrollbar reset) as the declared exceptions.
